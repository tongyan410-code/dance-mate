# 舞伴智练｜第一阶段真实用户试用方案

## 1. 试用目标

邀请 3—5 名社区中老年舞蹈爱好者，验证产品介绍中的核心学习闭环是否容易理解、能否完成、是否真的有帮助，并找出下一轮应优先修改的问题。这是小规模可用性测试，不代表市场规模或商业需求已被验证。

## 2. 招募对象与隐私

- 目标用户：平时参加社区舞蹈、现代舞、广场舞或其他舞蹈活动的中老年爱好者。
- 使用匿名编号：U01、U02、U03、U04、U05。
- 不必记录姓名、手机号、身份证号或精确年龄。
- 不默认录制用户测试过程；如需保留视频、照片或可识别影像，必须单独说明用途、保存方式、访问人和删除时间，并取得明确同意。

## 3. 建议测试任务

| 模块 | 用户任务 | 观察重点 |
|---|---|---|
| 动作学习 | 找到教师示范或动作讲解，理解一个动作片段 | 是否知道看哪里；讲解是否容易懂 |
| 我的练习 | 选择/录制一段自己的练习视频 | 授权是否清楚；是否会选视频；是否能完成上传 |
| 动作对照 | 查看示范与练习的并排视频和骨架结果 | 是否理解两边内容；是否看懂“辅助观察”；是否误以为系统在打分 |
| AI 陪伴 | 提出一个真实练舞问题，再追问一次 | 是否有帮助、是否听得懂、是否答非所问、是否知道它的能力边界 |
| 持续使用意愿 | 询问下次是否愿意再用以及原因 | 记录真实表达，不引导用户给好评 |

如同时邀请教师试用，可额外测试教师创建课程、上传示范、手动切分、填写讲解、审核和发布流程。

## 4. 每个任务记录哪些数据

- 匿名用户编号、日期、设备类型和浏览器；
- 是否完成（完成/部分完成/未完成）；
- 是否独立完成（独立/需要提示/需要代操作）；
- 大致耗时；
- 求助次数；
- 满意度（1—5 分，可不填）；
- 用户原话或观察到的问题；
- 建议修改项及复测结果。

不要为了“有数据”而编造数据。未完成的任务也要如实记录。

## 5. 试用后访谈问题

1. 哪个功能最有用？为什么？
2. 哪一步最难找或最难操作？
3. 动作对照的提示是否容易理解？有没有让你误以为 AI 在给动作打分？
4. AI 陪伴的回答是否解决了刚才的问题？哪里不合适？
5. 如果下次练舞，你愿意再次使用吗？为什么？

## 6. 汇报时可呈现的指标

- 邀请人数、实际完成试用人数；
- 每项任务的完成率和独立完成率；
- 需要协助的任务数、平均/中位耗时（样本很小时同时展示原始数量）；
- 用户最喜欢的功能；
- 高频问题前三项；
- 根据反馈完成的修改项；
- 修改后复测结果。

样本量只有 3—5 人时，请使用“本轮试用中”“初步发现”等表述，不要声称代表所有社区中老年舞蹈爱好者。
